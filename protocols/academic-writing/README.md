# 学术写作的论证、层级与可核验修订协议

**版本：2.0.0 · 语言：中文 · 形式：可直接作为提示词使用的 YAML**

[打开完整协议](protocol.zh-CN.yaml) · [返回仓库首页](../../README.md)

本协议适用于论文、学位论文、项目申请书、研究报告和研究讨论，重点约束问题提炼、概念层级、论证关系、证据使用与修订执行。英文写作、审稿回复、图表公式、逐页展示和文件写回按任务启用。

协议可以独立复制到对话中使用，不需要安装技能，也不依赖私人会话、压缩包或本地路径。YAML 是规范的组织形式，不是自动执行器；实际文件操作仍需相应工具和授权。

## 使用方法

将完整的 `protocol.zh-CN.yaml` 作为上下文或附件提供给执行者，再附实际材料和本轮任务。最简调用方式：

```text
请依据附件中的《学术写作的论证、层级与可核验修订协议》完成本次任务。

目标：[希望解决的问题或得到的正文]
材料：[稿件、章节、指南、参考资料或实际结果]
修改模式：[局部修改／实质重写／结构调整／仅审阅／起草／研究讨论／仅格式]
范围：[允许处理与需要保留的部分]
交付：[正文、修改对照、文件；若需写回，明确目标和是否覆盖]

按本次材料和要求启用相关规则。已有信息足够时直接执行，仅询问真正阻塞的事项。
```

不需要每次填写协议里的所有配置项。已有材料能够确定的条件由执行者识别；简单改句不必启动完整文档审阅。

## 核心规则

| 方面 | 要求 |
|---|---|
| 论证主线 | 将对象、困难、已有不足、科学问题、方法与证据对应起来。 |
| 层级职责 | 分开研究内容、目标、科学问题、方案、实验和贡献；图和公式服务于所在层级。 |
| 句段组织 | 一句话有一个主要论点，一段有明确任务；并列项必须同层、同类且有作用。 |
| 实质改写 | 通过概念关系和论证组织解决堆砌；保留必要技术定义、假设与实现依据。 |
| 修改范围 | 局部修改保持范围；已授权的重写处理真实结构问题；仅审阅不自动写回。 |
| 证据与结果 | 分开事实、假设和已验证结果；统计单位、比较条件、图表和正文保持一致。 |
| 来源归属 | 区分用户原话、忠实转述、助手建议与执行经验；不将归纳冒称为原话。 |
| 完成状态 | 起草、展示、写入、渲染、验证和发布分别核实。 |

## 逐页修订

用户要求逐页展示时，采用修改前的真实页面及段落映射。每一页先在聊天中展示完整原文与完整改稿，再审查；审查改变文字时，先补充展示最终稿，之后才执行已授权写回。

过长页面可分块展示，全部展示后才能写入。跨页段落首次出现时整体展示并记录跨度，后续页面说明承接关系。修改后允许自然重排，不能把新分页冒称原分页。

已有授权内自动继续，无需逐页索取批准。用户明确要求逐页审批时采用该流程；用户打断时停止尚未执行的操作，说明已完成状态并调整后续任务。

## 通用规则与项目条件

模型规模、输入预算、具体标题、图号归属、术语替换和研究架构应放入本轮 `project_profile`。它默认关闭，只有当前任务明确确认相应范围时才启用。

协议中的表征共享检查是可选示例，用于说明如何区分信息收益、计算收益、适配成本和成立条件。它不要求其他研究采用 KV 共享、特定模型或某种协作架构。

`Q/U/A/P` 用于执行时辨认来源：`Q` 为能逐字定位的用户片段，`U` 为忠实转述，`A` 为助手归纳或建议，`P` 为实际执行经验。协议条文本身是归纳后的规范，不宣称全部来自用户原话。公开文件不包含私人对话、身份映射或未公开论文附件。

## 与仓库原有功能的关系

本目录提供独立的通用写作与修订提示词。仓库原有英文摘要技能、词汇规则和评分脚本继续用于其原定任务。脚本评分不能验证本协议中的事实真实性、研究贡献或文件操作完成状态；应用本协议需要结合实际材料逐项判断。
